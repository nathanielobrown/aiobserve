# Testing plan: viewer polish — one naming system, richer popovers, a readable reading pane

Obligations for `plans/viewer-polish/design.md`, grouped by that design's slices so each is due with its code. Every leaf is an obligation; the *Evidence:* clause names the artifact that discharges it, and an auditor traces each leaf to that artifact. Where a leaf names an existing test, the obligation is to extend or edit that test — a rule that changed while its test did not is a rule nothing checks.

Three rules shape everything below.

- **The seam is served bytes.** Assertions run through `TestClient` over the fixture corpus and read values out of `data-` attributes, never out of rendered prose and never out of the store the page read (`tests/view/conftest.py` docstring). The exceptions are the two pure modules — the formatter registry and the inline-markdown renderer — which test as functions
- **A recorded session beats an invented record, but redaction flattened the strings.** Every fixture README redacts the strings under a tool `input`, and no fixture records a model's enrichment, so markup and long values are planted onto real rows with `plant` / `enriched_plant` (`tests/view/conftest.py:planter`). A leaf that plants says so
- **What only a browser can show is driven or eyeballed, not asserted.** Popover fetch and placement belong to `tests/e2e/specs/htmx.spec.ts` (`mise run e2e`); colour, border weight and badge shape are witnessed on `mise run gallery` and dated in `.claude/rules/viewer-ui.md`

## Levels

- **unit (naming)** — `tests/view/test_formatters.py`. A tool name and the `tool_fields` column set in, `Formatted(mark, words)` out. No app, no store
- **unit (inline markdown)** — `tests/view/test_render.py`, beside the block renderer's safety pins, since the two share every escaping question
- **served HTML (NavTree)** — `tests/view/test_nav_tree*.py` over the session-scoped `client` fixture; rows read by `rows`/`fields`/`inside`/`values`
- **served HTML (node page)** — `tests/view/test_node*.py`, `test_walk.py`, `test_errors.py`, `test_run.py`
- **served HTML (fragments)** — `tests/view/test_numbers.py` over the `/fragment/numbers/…` routes, expectations priced from `live_api_calls` in the test's own SQL as that file already does
- **bounds and budgets** — `tests/view/test_bounds*.py` against `tests/view/budgets.py` and `src/hyphae/view/bounds.py`
- **fixture evidence (extract tier)** — a redacted excerpt proves the fields the viewer's queries then read
- **browser tier** — `tests/e2e/specs/htmx.spec.ts` under `mise run e2e`
- **eyeballed** — `mise run gallery` on `tests/view/scenarios.py`, witnessed and dated in `.claude/rules/viewer-ui.md`

## Slice 3 — inline markdown

- **Bold, italic and code render in a title; a link renders as an anchor only outside an existing link.** *Evidence:* one enrichment description planted through `enriched_plant` carrying `**bold**`, `` `code` `` and `[PR #18](https://github.com/…)`, read on four surfaces of the same node: the reading-pane `<h1>` carries a `<strong>` and an `<a href>`; the NavTree row, the crumb chain and the walk control carry the `<strong>` and the link's text with no nested `<a>`. Bolded: link-inside-a-link is the failure the design's rule exists to prevent, and only reading the same planted string on both kinds of surface catches it.
- The `<title>` element and every attribute carry plain text. *Evidence:* the same planted page's `<title>` holds neither `**` nor `<`, and no `data-` attribute on the page contains a tag.
- **The inline renderer passes the block renderer's safety pins.** *Evidence:* leaves beside the existing ones in `tests/view/test_render.py` — raw HTML in the source arrives as text (`:13`), an inline `onerror` attribute cannot ride in (`:28`), image syntax fetches nothing (`:35`), and only an `http` URL becomes a link (`:59`) — run against `inline_markdown.render`. Bolded: the new module is a second escape path into every page, and `test_app__safety.py`'s CSP leaf does not see string composition.
- No block element escapes into a title. *Evidence:* a planted description holding a heading, a list and a fenced block renders to text with no `<h`, `<ul>`, `<p>` or `<pre>` in the NavTree row.
- Width cuts measure the plain text. *Evidence:* `test_a_crumb_is_cut_narrower_than_every_other_place_a_title_is_read` (`test_node.py:456`) extended with a planted title whose markdown syntax exceeds the crumb cut — the visible characters count to the same length as the same title without syntax, so the asterisks do not eat the budget.
- A title with no markdown in it is byte-identical to what it was. *Evidence:* over every fixture session, every NavTree row title on the unplanted corpus matches the value the store holds, so the renderer is a no-op on flat text.

## Seam findings for the designer

- **The ported fallback needs a field the design's contract does not ship.** `name_tool(fields)` takes "the `tool_fields` column set", but the fallback's last arm is the head of the raw input JSON, and `tool_fields` carries no such member. Today the queries hand Python both `tool_fields` and `tool_title`, and `builders.tool_node` falls back to the latter (`view_nav_tree_tools.sql:22`, `builders.py:188`). Either `tool_fields` gains a bounded `head` member or the queries keep shipping a cut `input`; both stay inside the byte scan, but the design should say which. The slice-1 fallback leaf is unreachable until it does.
- **The design says `tool_asked` and `tool_path` are deleted, but `tool_fields` calls both.** `macros.py:_TOOL_FIELDS` is built out of them, and `tool_path` is what relativizes a path against the project. Read as a slip for "`tool_title` and `tool_about`"; confirm before the implementer deletes anything.
- **The formatter table has no served-HTML evidence beyond the tools the corpus records.** Every fixture README redacts the strings under a tool `input`, so a served row proves the registry fired, not what it read. `ToolSearch` and `PushNotification` escape this only because slice 0's cut keeps their arguments — which is why that cut's README has to state the redaction call on the `PushNotification` message. Widening the corpus's redaction rule is a decision about the whole fixture set, not about this change.

## Unreachable

Nothing in the design is unreachable through its seam once the two macro findings above are settled. The fallback leaf under slice 1 is the one obligation blocked on a design answer rather than on implementation.

## Not covered

- **Anything CSS computes.** Border weight and colour, badge shape, the depth of a wash, popover geometry beyond the top-alignment the browser tier already asserts. The server emits classes; the browser decides what they look like. Eyeballed on the gallery and dated in `.claude/rules/viewer-ui.md`
- **Markdown in detail values beyond what already renders as prose.** Out of scope in the design; the existing leaves in `test_node__details.py:93` are regression cover
- **The popover script itself.** No JS test runner in this repo. The obligation stops at what `mise run e2e` drives and at `test_the_popovers_placement_rides_a_file_the_policy_allows` (`test_numbers.py:335`)
- **Per-turn and per-session compaction badges.** Out of scope in the design; no query exists to feed them
- **The cost badge and the context bar.** Untouched by this change; their leaves in `test_nav_tree__badges.py` and `test_nav_tree__bars.py` are regression cover, not obligations of this change

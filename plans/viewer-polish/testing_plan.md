# Testing plan: viewer polish — layout, NavTree, formatters, badges, bars

Obligations for `plans/viewer-polish/design.md`, grouped by the design's slices so each is due with its code. Every leaf is an obligation; the *Evidence:* clause names the artifact that discharges it, and an auditor traces each leaf to that artifact.

Three rules shape everything below.

- **The seam is served bytes.** As everywhere in the viewer tier, assertions run through `TestClient` over the fixture corpus and read values out of `data-` attributes, never out of rendered prose and never out of the store the page read (`tests/view/conftest.py` docstring). The one exception is the formatter registry, a pure function that tests as one
- **The kind × preset table is the nesting expectation.** `cell` in `tests/view/nav_trees.py` spells out every cell of the design's table, built from the store in the test's own SQL. The nesting rework is an edit to `cell` before it is a passing test — a rule that changed without `cell` changing is a rule nothing checked
- **What only a browser can show is eyeballed, not asserted.** Sticky clamping, band colours, popover placement: the HTML asserts the class and the structure, and the look is checked on `mise run gallery` and recorded per the protocol in `.claude/rules/viewer-ui.md`

## Levels

- **unit (formatters)** — `tests/view/test_format.py`. A tool's name and extracted fields in, `(lead, words)` out. No app, no store; `Corpus.runs` is passed as the small mapping the registry declares
- **served HTML (NavTree)** — `tests/view/test_nav_tree*.py` over the session-scoped `client` fixture. Rows read by `rows`/`fields`/`inside`/`values`; expectations built from the store by `nav_trees.cell`
- **served HTML (node page)** — `tests/view/test_node*.py`, `test_walk.py`, `test_render.py`. Crumbs, titles, the footer's place in the document
- **served HTML (popover)** — `tests/view/test_numbers.py` over `NUMBERS_URL`, with expectations priced from `live_api_calls` in the test's own SQL, as that file already does
- **bounds and budgets** — `tests/view/test_bounds*.py` against the measurements in `tests/view/budgets.py` and the caps in `src/hyphae/view/bounds.py`
- **extract tier (new fixtures)** — `tests/extract/`, where a newly redacted transcript proves the fields the viewer queries then read
- **eyeballed (gallery)** — no automated test. `mise run gallery` on the scenarios in `tests/view/scenarios.py`, witnessed and dated in `.claude/rules/viewer-ui.md`

## Slice 0 — fixture evidence, due before slices 3 and 5

The design's §Test seam names the three cuts and the reasoning behind each. The leaves below are what discharges them.

- **A SendMessage whose `to` resolves to a run of the same session.** `tests/fixtures/parallel_tools` is re-cut rather than replaced: its README's tightening is loosened to keep `to`, and each addressed run's opening records and `meta.json` come in so the id has a row. Its three sends address run ids resolving to `general-purpose` and `auditor` — the id population, which is the arm that reads beyond its own tool call. `teammate`'s sends are the *name* population (`to: "architect"`), which the fallback prints verbatim, so they would prove the arm needing no lookup. *Evidence:* the amended README states the source session, the Claude Code version, and the sensitivity call the design spells out; a store built from the fixture answers `SELECT count(*) FROM tool_calls t WHERE t.name = 'SendMessage' AND json_extract_string(t.input, '$.to') IN (SELECT id FROM agent_runs r WHERE r.session_id = t.session_id)` with a non-zero count.
- The compaction record's fields, confirmed against a recording before any query reads them. Already confirmed in this worktree: `compactMetadata` on `tests/fixtures/compaction/1de7cf38-…jsonl` (CC 2.1.198) carries `trigger`, `preTokens`, `postTokens`, `durationMs`, `cumulativeDroppedTokens`, `preservedMessages`, `preservedSegment`, `preCompactDiscoveredTools`; `Compaction.pre_tokens`/`post_tokens` already model the two the bar needs and the `compactions` table already stores them. *Evidence:* `src/hyphae/extract/records/shapes.py:CompactMetadata` and `evidence.py:COMPACTION` cite that fixture; `docs/schema.md` prints it. No extractor change is due — the slice-5 query selects columns that exist.
- **A run whose own thread compacted.** No fixture has one; the local store holds 1,124. The design names the smallest — session `6eea741c-1a7e-42a1-b242-ef3f8f02cb6b`, run `a3ad46668652aaa4f`, `general-purpose`, CC 2.1.220, one `auto` boundary at 174,580 → 21,486 on `claude-sonnet-5` — which gets its own fixture directory, since a second excerpt of a session already in the corpus would export twice under one id. Redact the run's `compact_boundary`, the api calls around it, its `meta.json`, and the main-thread records its spawning Agent call sits in. *Evidence:* a store built from the new fixture answers `SELECT source FROM compactions WHERE source <> 'main'` with the run's id; the session and run ids become named constants in `tests/conftest.py` beside `COMPACTED`. Re-run the smallest-candidate query before cutting — the store grows, and a smaller one may have landed.
- **The compaction fixture can name a window.** `tests/fixtures/compaction` holds two boundaries and **zero api calls**, so its session names no model. It is re-cut from the same recording to carry the last assistant record before each boundary and the first after. *Evidence:* a store built from it answers, for each `compactions` row, a non-NULL `context_window(model)` off the nearest non-synthetic `api_calls` row of the same `session_id` and `source` — the query the ⊟ bar leaf under slice 5 cites. The post-boundary call is what makes the leaf a reading of a real rebuild rather than of one number.

## Slice 2 — nesting rework

- **Every kind × preset cell opens exactly the children the table names, with hoisting gone.** *Evidence:* `cell` in `tests/view/nav_trees.py` rewritten — `hoisted` splicing deleted from `turn_level` and `tool_level`, `(Kind.TOOL, FULL | NO_API)` returning the run instead of `[]` — and `test_every_kind_under_every_preset_opens_the_children_its_cell_defines` (`test_nav_tree__presets.py:120`) green over every node of every fixture session. Bolded: this table is the one place the nesting rule is written down twice, and a rule that changed in `nav_tree.py` alone would pass nothing.
- A run renders under its ⇄ Agent tool call when the api call is open. *Evidence:* on a `spine` page selecting an api call that spawned a run, `rows(html)` shows `run:<id>` immediately after `tool:<spawn tool id>` and one `data-depth` deeper.
- **A run whose ancestor rows are closed still renders, one level under the nearest visible ancestor.** *Evidence:* three readings of the same run in one leaf — closed api call (run directly beneath the call row, no tool row present), `nav=noapi` with a closed turn (run beneath the turn row), `nav=agents` (run beneath the session or its parent run) — each asserting the run's key is present and its depth is its visible parent's plus one. Bolded: "always visible" is the rule that replaced the hoisting machinery, and only a closed-ancestor reading can catch a run that fell out of the tree.
- Deleting `_hoisted` leaves no run unreachable in any preset. *Evidence:* over every fixture session and every preset, the set of `run:` keys the NavTree draws from the session page equals the session's `agent_runs` ids — a sweep, not a spot check.
- An agent run's row leads with `[agent_type]`. *Evidence:* the run row's text begins `[architect]` on the `teammate` session, and no row on any page matches `<agent_type> —`.
- The open path stays open and the selection stays selected under the new nesting. *Evidence:* `test_the_nav_tree_opens_the_selections_path_and_leaves_the_rest_shut` (`test_nav_tree.py:193`) and `test_a_preset_hides_a_kind_without_hiding_the_path_down_to_one` (`test_nav_tree__presets.py:207`) pass unchanged.
- The kin cap and the tail row still cut the level the new rule builds. *Evidence:* `test_the_kin_cap_cuts_the_children_but_never_the_open_path` and `test_a_tail_row_stands_the_rest_of_its_level_where_it_stands` (`test_nav_tree.py:293`, `:328`) pass against the reworked levels.

## Slice 3 — formatters, 💭, crumb head, 40-char cut

- **Each of the twelve tools in the design's table renders its named lead and source field.** *Evidence:* a table-driven unit leaf in `tests/view/test_format.py`, one case per row of the design's formatter table, asserting `(lead, words)` — `Bash` from the first line of `command` and not `description`, `Skill` appending args only when present, `TodoWrite` counting items. Inputs are lifted from recorded fixture `tool_calls.input` where the corpus has that tool, and labelled invented where it does not (`WebSearch` and `Glob` are not in the fixture corpus — check at implementation rather than trusting this sentence). Bolded: twelve small rules is where a table drifts from its documentation.
- A tool the registry does not name keeps today's `Name - <shape-driven title>`. *Evidence:* a served-HTML leaf over every fixture session asserting that every tool row whose `name` is outside the registry still matches the `tool_title` macro's output for that row, read from the store.
- **SendMessage resolves `to` to the addressed run's agent_type, and prints anything else as recorded.** *Evidence:* the re-cut `parallel_tools` for the lookup — a row reading `📬 to auditor: …` where the store's `input.to` is that run's id, so the served word is one the tool call does not contain; `tests/fixtures/teammate`, whose main-thread sends carry the name form (`to: "architect"`), for the fallback printing `to` verbatim. Bolded: this is the one formatter that reads beyond its own tool call, and the only branch a redaction can silently disable — the resolving row must assert a word absent from the row's own `input`, or an implementation that never received `Corpus.runs` would pass.
- Paths in a formatted row are relativized against the session's project. *Evidence:* a `Read` or `Edit` row on a mycelia fixture session reads `src/…` with no `/Users/nob/repos/mycelia` prefix, checked against `sessions.project`.
- **An api call whose words are model speech carries 💭, including one that also ran tools.** *Evidence:* over every fixture session, every `call:` row whose store `text` is non-empty carries the glyph and every row whose `text` is empty does not — a sweep, with the "also ran tools" case named explicitly by picking a call that has both `text` and `tool_calls` (`DENSE_CALL`'s turn on `ANCESTOR` has the shape; confirm at implementation).
- **One title everywhere.** *Evidence:* for one tool call of each registered name, the emoji lead appears in the NavTree row, in the crumb chain of that node's page, in the reading pane heading, and in the parent's children-log row — four surfaces, one asserted string. Bolded: the doctrine is what makes the formatters worth having, and it is asserted nowhere else.
- Crumbs cut at `CRUMB_CHARS = 40` while walk, error stepper, and tab title keep 110. *Evidence:* a page whose node title exceeds 40 characters; the crumb text length is ≤ 40 plus the ellipsis and the walk link's text is not, both read from the same page. `CRUMB_CHARS` is defined once, in `analyze/queries.py` beside the other cuts — `grep` finds `40` there and no literal 40 in `nodes.py`.
- The crumb chain leads with 🏠 linking the session list and a home-relativized project path linking that project's filtered list. *Evidence:* on a mycelia fixture page, the first crumb's `href` is `/sessions`, the second's text is `~/repos/mycelia`, and its `href` is a `/sessions` URL whose project parameter is the one the filter form declares — read the parameter name off the served form, not from this plan.
- A session with no project still serves a crumb chain. *Evidence:* `NO_PROJECT_SESSION` (`tests/conftest.py`) renders 200 with the project crumb absent rather than a link to an empty filter.
- Every route still serves 200 with the new title pipeline. *Evidence:* the `scenarios.ROUTES` sweep in `tests/view/test_bounds.py` and `test_node.py:62`.

## Slice 4 — cost rollup and dual badges

- **A subtree total is never less than the node's own, on every node of every fixture session.** *Evidence:* a sweep over every NavTree row carrying two values, asserting `total ≥ own` and that `own` equals what the single-number badge showed before the change for the same key. Bolded: this invariant is the cheapest catch for a rollup that double-counts or attaches a run twice.
- A turn's total equals its own thread cost plus the cost of every run its tool calls spawned, transitively. *Evidence:* `test_nav_tree__meters.py` leaf computing the expectation from `live_api_calls` and the `SPAWNS`/`parent_agent_id` edges in the test's own SQL, over `spine` — which has a run and a nested leaf run (`SPINE_RUN`, `SPINE_LEAF`).
- The session row reads `$main/$whole`, and `$whole` equals `session_rollups.cost_usd`. *Evidence:* the session row's two values against that column, so the badge agrees with the number the rest of the viewer cites.
- **The ⇄ Agent tool row's own value is its invoking api call's cost.** *Evidence:* on `spine`, the Agent tool row's `own` equals `live_api_calls.cost_usd` for the call holding it, and its `total` equals that plus the spawned run's subtree; a second assertion covers the accepted quirk — two Agent calls in one api call each claim the full call cost, so their `own` values are equal and their sum exceeds the call. Bolded: this is the one attribution the design knowingly overcounts, and the test is what stops someone "fixing" it silently.
- A row with no run cost under it keeps a single number, and a non-Agent tool row keeps none. *Evidence:* the existing `test_a_row_badges_its_cost_only_where_it_has_a_share_to_draw` (`test_nav_tree__meters.py:40`) extended: rows carrying `cost_usd` and no subtree run cost have exactly one badge span; `Bash`/`Read` tool rows have none.
- Each half of a dual badge takes its own wash, stepped against the session whole. *Evidence:* `weighed`-style assertion per half — the step class on each span equals `meter(value / session whole)`, so the two halves cannot share one class.
- A badge does not move between presets. *Evidence:* the existing cross-preset stability assertion in the same leaf, now comparing the pair rather than the single value.
- The rollup is computed once per page. *Evidence:* the page's citation footer names the same query count as before, and the payload sweep in `tests/view/test_bounds.py` stays under its byte budget — a per-row rollup query would show as neither, so name this leaf's real check: `test_the_same_node_url_serves_the_same_bytes_cold_and_warm` (`test_node.py:359`) plus the re-measured row budget below.

## Slice 5 — bars

- **A turn's bar draws three bands, and they order base ≤ prior ≤ fill.** *Evidence:* over every turn row of every fixture session, the three step classes parse back as non-decreasing integers, each ≤ `BAR_STEPS`. Bolded: three bands is a new class vocabulary, and an inverted pair is the failure a reader would see as a bar drawn backwards.
- The base band equals the session's first main-thread api call's cache-read plus new-input tokens, stepped against the window. *Evidence:* `test_nav_tree__meters.py` leaf computing the base in the test's own SQL over `spine`, and asserting the same class on turns from different points of the session — the base is a session constant, so it must not vary row to row.
- A session whose first call is a resume inherits a fat base rather than crashing or clamping to zero. *Evidence:* `RESUME` (`tests/conftest.py`) renders a base band above zero; the caveat is accepted in the design, so this leaf pins the accepted behaviour rather than an ideal one.
- This turn's delta stays clamped at zero across a compaction. *Evidence:* on the compaction fixture session, the turn whose span covers a boundary shows a delta band of `t0` rather than a negative or wrapped step.
- **A run whose thread compacted draws a full-width red bar.** *Evidence:* the new slice-0 fixture, whose `compactions` row carries the run's id as its `source`; that run's NavTree row carries the red-full class and `SPINE_RUN`, whose thread did not compact, does not. Bolded: this is the design's one new warning signal, and no existing fixture can produce it.
- Run bars carry the run hue class, turn bars do not. *Evidence:* a class-presence sweep over `run:` and `turn:` rows on every fixture session.
- **A ⊟ row draws dim to the post-compaction fill and green from there to the pre-compaction fill.** *Evidence:* on the re-cut compaction fixture, the ⊟ row's two step classes computed in the test's own SQL from that row's `pre_tokens` and `post_tokens` over `context_window(model)` of the thread's nearest non-synthetic api call — the same expression the query uses, read from the store rather than copied here, since the recorded numbers move when the excerpt is re-cut. Bolded: it is the slice's most-specified visual and the one whose inputs are a fresh query.
- **A ⊟ row whose thread names no window draws no bar.** *Evidence:* a copied store with the compaction fixture's api calls stripped — the shape `tests/view/conftest.py` plants for values no fixture carries — serves the ⊟ row with its facts and no band class at all. Bolded: NULL is the design's whole degrade path for a schema it does not control, and it is the one arm no recorded session will produce on demand.
- Every model the price table holds has a 200,000-token window, so no served value distinguishes the per-thread window from a session-wide one. *Evidence:* none — recorded here so a later reader does not mistake the arithmetic leaf above for proof of where the window came from. The rule is settled in the design on meaning; `CONTEXT_WINDOWS` gaining a model of another size is what would make it assertable.
- The classes are CSS hooks only; no inline style reaches a bar. *Evidence:* the existing CSP leaf (`tests/view/test_app__headers.py`) plus an assertion that no `style=` attribute appears on any `data-nav-tree` row or its descendants.
- The bands and hues read correctly in both colour schemes. *Evidence:* eyeballed on `mise run gallery` in light and dark, dated in `.claude/rules/viewer-ui.md` — the design leaves the dark-mode tokens to implementation.

## Slice 6 — popover, alignment, scroll restore

- **The popover's four rows and its total sum, with new input's dollar covering input plus cache write.** *Evidence:* `tests/view/test_numbers.py` leaf pricing `live_api_calls` a call at a time in its own SQL, as that file already does: the three token figures sum to the total's `+N`, and the four dollar figures sum to the total's dollar to cent precision. Bolded: "so columns sum" is the whole reason the design moved cache-write cost into the new-input row, and only arithmetic across the whole block proves it.
- `over N api calls` appears only when N > 1. *Evidence:* one node whose subtree holds a single api call (a `call:` row) and one holding several (a turn on `spine`); the line is absent from the first and names the store's count on the second.
- Each dollar figure carries a wash stepped by its share of the session whole, reusing the badge meter. *Evidence:* per-row step class equals `nodes.meter(value / session whole)` — the same function, asserted by name so a second implementation would diverge.
- The Agent tool row's popover names the attribution in words. *Evidence:* the popover for a ⇄ Agent row contains the attribution line the design specifies, keyed by a `data-` attribute rather than matched as prose.
- Every kind the design gives a popover still answers 200, and ⊟ and bucket rows still have none. *Evidence:* the `NUMBERS_URL` sweep over `scenarios.ROUTES`; compaction and bucket rows carry no `hx-get` to `NUMBERS_URL`.
- The static script is a real file, served, and referenced from a scripts block — nothing inline. *Evidence:* `GET /static/nav-tree.js` is 200 with a JS content type; the node page's HTML contains no inline `<script>` body and no `onclick`-style attribute; the CSP header leaf stays green.
- **Popover placement and scroll restore behave in a browser.** *Evidence:* eyeballed on `mise run gallery` — popover top-aligned to the hovered row with its left at the NavTree's edge, repositioning on hover and on NavTree scroll; a deep selection centred in the scroller on load. Dated in `.claude/rules/viewer-ui.md`. Bolded: it is the slice's user-visible payoff and unreachable from served HTML, which carries only the script tag.

## Seam findings for the designer

The three findings this plan raised are settled in `plans/viewer-polish/design.md` — the window source and the three fixture cuts under §Test seam, the `to` resolution rule under §Key contracts. One finding stands, because it is a behaviour the design accepted rather than a gap.

- **Parallel Agent spawns overcounting is asserted, not fixed.** The leaf under slice 4 pins the behaviour the design accepted. If that reads wrong to a user later, the test is what will have to change with it.
- **The formatter table's twelve leads have no served-HTML evidence beyond SendMessage.** Every fixture README redacts every string under a tool `input`, `file_path` and `command` included, so a served row can only prove that the registry fired — not what it read. The slice-3 table leaf is a unit over invented inputs by necessity, and the path-relativization leaf needs a fixture that keeps a `file_path`. Raised here rather than fixed: widening the corpus's redaction rule is a call about the whole fixture set, not about this change.

## Not covered

- **Anything CSS computes.** Sticky-ancestor clamping and its per-depth offsets, band colours, hue choices, the absence of a document scrollbar, popover geometry. The server emits classes and structure; the browser decides what they look like. These are eyeballed on the gallery and dated in `.claude/rules/viewer-ui.md`, which is the protocol the scroller rule already uses
- **The ≤900px block layout beyond what it already has.** Out of scope in the design; no new leaf
- **The popover JS itself.** No JS test runner in this repo. The obligation stops at "the file is served, referenced, and CSP-clean"
- **Reading-pane bodies, logs, details, walk, and the error stepper.** Untouched by the design; their existing leaves are regression cover, not obligations of this change
